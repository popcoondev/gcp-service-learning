# Pub/Sub

## 何のために使うか

注文作成後の後続処理を非同期化し、API 応答時間と downstream 結合度を下げるために使います。

## どのような構成で使うか

- `OrderCreated` イベントを topic に publish する
- subscriber で通知、分析連携、補助処理を分離する

## このサンプル内でどこに登場するか

- 現時点では未実装です
- `application` から直接 SDK を呼ばず、将来 `EventPublisher` port を追加する前提です

## PM視点で何が難しいか

- 非同期化で責任境界が見えづらくなる
- 再送や重複時の業務影響整理
- SLA を同期 API と別管理する必要

## 開発者視点で何が難しいか

- 少なくとも一回配信を前提に冪等設計が必要
- ローカル検証と本番権限差分
- エラー時の DLQ 戦略
